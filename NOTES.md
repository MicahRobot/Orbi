## Decisions

Calls made where the spec was ambiguous. Change one by editing it here in the same PR as the code.

- **Three lanes, no lead.** A = screens & data, B = ears & brain, C = face & teacher (joins later). Instead of a lead owning `shared/`, contract changes need someone from another lane to approve (docs/WORKFLOW.md §3).
- **Spec v2 (3-hour build).** Folded in the 3D-teacher plan's UI pieces and left out what overlapped or couldn't be built accurately in time; the table is at the end of SPEC.md.
- **Required stack.** Gemini (Google DeepMind) replaces Claude for coaching and also generates reference audio; Supabase stores profiles and attempts. Model ids (`gemini-3.5-flash-lite`, `gemini-3.8-flash-tts`) are from the Gemini models page on 2026-10-10 and can be overridden with `GEMINI_COACH_MODEL` / `GEMINI_TTS_MODEL`.
- **Match ring.** Match = mean of syllable tone scores, a syllable with a severity-3 card capped at 40. Green ≥ 80 with no severity 2–3 card; red with any severity-3 card; amber otherwise. A pass (for streaks and `AttemptRecord.passed`) = no card of severity 2 or 3.
- **Calibration** is one ~10-second flow (glide, ee, oo, ah; neutral face captured during the instructions) instead of v1's 25-second one plus the plan's separate 5-second one.
- **All web dependencies pre-installed** (three, react-three, MediaPipe, supabase-js) so no two lanes edit `package.json` in the first hour.
- **Fixture layout.** `shared/fixtures/analysis/<promptId>.<variant>.json` (`AudioAnalysis`), `face/<same name>` (`FaceSummary[]`), `index.json` (every fixture plus the fix cards `diagnose()` should return), `calibration.json`. All generated by `make_fixtures.py`; regenerate rather than hand-edit.
- **Pitch rule order.** When a syllable's target has a `sandhiNote`, `wrong_tone` wins so the card can explain the sandhi rule (nihao.full_dips → `wrong_tone`). Otherwise a specific detector beats the generic `wrong_tone` (ma4.t2_dip → `t2_late`, whose message already says "sounds like tone 3").
- **Tone issue severity.** The spec sets `wrong_tone` and `no_pitch` to 3 and `t3_full_in_context` to 1. All other tone issues are 2.
- **"Min falls after point 4"** (`t2_late`) means the lowest of the 10 points sits at zero-based index 4 or later.
- **`nearest`** compares T1, T2, T3_full, T3_half and T4 only. T5's height depends on the previous tone.
- **laoshi.** lao3 → `T3_half` gets a `sandhiNote` so the UI can explain the half third tone.
- **Service fixture mode.** `/analyze` returns `<promptId>.correct.json` whatever audio it receives; the web app's own fixture mode is the way to replay wrong attempts.
- **Sandhi (B1) details.** 不 and 一 are found by their hanzi, not the pinyin (yi1 can be other words). 一 before a neutral tone is left alone. `reading: "list"` skips all sandhi, not only the half third tone. Notes read "不 before tone 4 → bú", "一 before tone N → yí/yì", "3+3 → 2+3", "half third tone: stays low"; a 3+3+3 run gives "3+3 → 2+3" on both changed syllables.
- **Vowel rules (Module E) details.** Audio decides, so 女 heard as "ee" gets `y_lips_not_rounded` whatever the lips show (the table only lists spread/partly). Without a face (coverage < 0.5) lip conditions are skipped: heard "ee" → `y_lips_not_rounded` with the `_audio` message naming both causes; heard "oo" → `y_both`; `y_ok_lips_hint` needs a face. `y_glide` and `y_both` count as `lips`, `y_tongue_back` and `u_fronted` as `tongue`. `u_fronted` and `i_rounded` are severity 3.
- **Card selection.** Per syllable the highest-severity match wins; on a tie the vowel card beats the tone card (vowel rules come first in `rules.ts`). Severity-1 info cards are returned too, after the fixes, inside the two-card limit.
- **Cautious wording.** A vowel card with confidence < 0.3 starts with "It's a close call, but try this: ".
